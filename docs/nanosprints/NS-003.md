# NS-003 — Per-agent model map in LLMConfig

**Status:** DONE — 2026-07-05
**Vision link:** VISION.md → Phase 0 — Foundation. Grows the 2-tier {model, being_model} into a per-agent model map (opt-in, defaults = today), enabling per-agent brain swaps (gemini/claude/local) without code edits — feeds Phase 3 and the parked Claude-brain thread.

## Scope

1. `LLMConfig` gains `models: dict[str, str] | None` (agent-name → model id),
   plus optional per-agent `api_base`/`api_key` overrides map. Absent → exact
   today's behavior (`model` for loops, `being_model` for Being).
2. `create_agents()` resolves each agent's model via a single
   `model_for(agent_name)` helper (planner keeps its dedicated
   response_format instance, now built from `model_for("planner")`).
3. `config.local.yaml` documented example (commented) showing a per-agent map.

## Out of Scope

- Any change to default behavior or current config files' effective values
- Claude/Anthropic gateway wiring (still blocked on key/quota)
- Event seam (NS-002), web UI (NS-004+)

## Acceptance Criteria (≤5)

1. With NO `models:` key in config, resolved model per agent is byte-identical
   to today (unit test asserts the full agent→model mapping).
2. With a `models:` map set (test fixture), each named agent gets its model and
   unnamed agents fall back to `model`/`being_model` correctly.
3. Planner's dedicated response_format instance survives (test: planner model
   is a distinct LiteLlm instance with response_format; others have none).
4. Full unit suite: failure set identical to the 13-failure maxfail-lifted
   clean-tree baseline; zero new failures.
5. Single revertable commit on the branch.
