# NS-001 — LiteLLM JSON-mode on direct-call sites + strict planner schema

**Status:** DONE — 2026-07-05
**Vision link:** VISION.md → Phase 0 — Foundation (kills the hand-rolled JSON pain in place, no framework change)

## Scope

Add `response_format` (JSON-mode / JSON-schema) to every direct LiteLLM call site
that today relies on `extract_json()` + shape coercion:

1. `agent/mood_resolver.py` — mood → intent-profile call
2. `agent/canonicalize.py` — both call sites (canonical track check, alias resolution)
3. Planner output: define a strict `PlaylistV1` JSON schema and pass it as
   `response_format` on the planner call in `planner_loop.py`

`extract_json()` and existing coercion stay in place **as fallback** — this
nanosprint adds the belt, it does not remove the suspenders.

## Out of Scope

- Removing json_extract.py or any coercion (measure first; removal is a later NS)
- Any ADK/Pydantic-AI change, any event-seam work (NS-002)
- Per-agent model map (NS-003)
- Prompt rewrites beyond what response_format requires

## Acceptance Criteria (≤5)

1. All 3 target call sites pass `response_format` and parse without invoking the
   extract_json fallback on gateway (gemini) models — verified by a debug counter/log
   line distinguishing "parsed direct" vs "fallback used".
2. Planner produces a schema-valid playlist on ≥3 consecutive live planner cycles
   (validate_playlist passes, 0 coercion warnings).
3. Full unit suite: no new failures vs baseline (55/56, 1 pre-existing).
4. Local-model path (Gemma config) degrades gracefully: if response_format is
   unsupported/ignored, fallback still parses (no regression vs today).
5. Change is a single PR off main, revertable in one `git revert`.

## Close summary

SHIPPED. All 4 LLM call sites now request JSON-mode; direct parses confirmed on
gateway; extract_json fallback retained and exercised only by design (local
models). Learnings:
1. json_schema response_format + tools through ADK = empty responses (gemini via
   gateway). json_object is the reliable mode for tool-bearing ADK agents —
   relevant input for the NS-008 Pydantic beachhead decision.
2. `parsed=direct` logs at DEBUG → invisible at daemon INFO level; absence of
   INFO fallback lines + successful writes is the live signal. Consider a
   PARSE_STATS surface in /http/status later.
3. Stale-daemon lazy imports can mix old objects + new modules → phantom
   verification signals. Always confirm daemon start-time vs commit-time.
4. Branch nuance: cut from fix/cost-accounting (repo state), not main — resolve
   at PR time (land fix/cost-accounting first or rebase).
